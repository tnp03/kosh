# RAG (Retrieval-Augmented Generation)

RAG is a technique that combines large language models with external knowledge retrieval. Instead of relying solely on the model's training data, RAG systems retrieve relevant information from external sources before generating responses.

## How RAG Works

### 1. Document Indexing

First, documents are processed and stored in a vector database:

```python
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter

# Split documents into chunks
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)
chunks = text_splitter.split_documents(documents)

# Create vector store
vectorstore = FAISS.from_documents(chunks, OpenAIEmbeddings())
```

### 2. Retrieval

When a query comes in, relevant documents are retrieved:

```python
# Search for relevant documents
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 3}
)
relevant_docs = retriever.invoke("What is machine learning?")
```

### 3. Generation

The retrieved context is combined with the query to generate a response:

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_template("""
Answer the question based on the context below.
If you can't answer the question, say "I don't know".

Context: {context}

Question: {question}
""")

llm = ChatOpenAI(model="gpt-4")
chain = prompt | llm

response = chain.invoke({
    "context": "\n".join([doc.page_content for doc in relevant_docs]),
    "question": "What is machine learning?"
})
```

## Benefits

1. **Up-to-date Information**: Can access current data beyond training cutoff
2. **Reduced Hallucination**: Grounded in factual, retrieved information
3. **Domain Specificity**: Can be customized with domain-specific knowledge
4. **Transparency**: Can cite sources for generated answers

## Challenges

### Chunking Strategy

How you split documents affects performance:

```python
# Fixed-size chunking
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)

# Semantic chunking
text_splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_percentile_threshold=95
)
```

### Embedding Quality

The quality of embeddings determines retrieval accuracy:

- **OpenAI Embeddings**: High quality, API-based
- **Sentence Transformers**: Open-source, local
- **Cohere Embeddings**: Optimized for search

### Context Window Management

Balancing context length with relevance:

- Retrieve too few documents: May miss relevant information
- Retrieve too many: May overwhelm the model with noise

## Advanced RAG Techniques

### Query Transformation

Improve retrieval by transforming queries:

```python
# HyDE (Hypothetical Document Embeddings)
from langchain.prompts import ChatPromptTemplate

hyde_prompt = ChatPromptTemplate.from_template(
    "Please write a passage that answers this question: {question}"
)
```

### Re-ranking

Re-rank retrieved documents for relevance:

```python
from langchain.retrievers import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import CohereRerank

compressor = CohereRerank(top_n=3)
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=retriever
)
```

### Multi-step Retrieval

Iteratively retrieve and refine:

```python
# Query expansion
expanded_queries = llm.invoke(f"Generate 5 related queries: {original_query}")

# Retrieve for each query
all_docs = []
for query in expanded_queries:
    docs = retriever.invoke(query)
    all_docs.extend(docs)

# Deduplicate and rank
unique_docs = deduplicate_and_rank(all_docs)
```
